Why I built it

The story

JARVIS started as an experiment to build an AI that could move beyond answering questions and actually coordinate tools, agents and workflows. Most assistants stop at the reply. JARVIS is built to act — route a request to the right model, call the right tool, and return a result you can watch happen.

It runs on the edge for speed and privacy, and on a calm chat surface when you want to see the work. The goal was never a bigger chatbot — it was a smaller, sharper system that feels less like software and more like a collaborator.

Project

JARVIS AI

A voice-first AI assistant that coordinates models, tools and agents from the edge.

What it does

  • Voice + text interface on web and mobile
  • Routes each request to the best-fit model (Groq, OpenRouter, local)
  • Calls external tools and runs multi-step workflows
  • Edge-hosted for low latency and privacy
  • Firebase auth so sessions are personal and persistent

Tech

  • Cloudflare Workers — edge runtime + KV cache
  • Firebase — Hosting, Auth, Google sign-in
  • Groq — primary low-latency inference
  • OpenRouter / Pollinations — fallback + media
  • Three.js — this cinematic interface
